# img2img helper

**img2img helper** — скрипт для Adobe Photoshop, который позволяет отправить выделенную область изображения в **ComfyUI** или **Forge Neo**, выполнить img2img/inpaint-обработку и сразу получить результат обратно в Photoshop отдельным слоем с маской.

Основной сценарий работы максимально простой: **выделить область → выбрать workflow или Forge-пресет → настроить параметры → Generate**. Ручной экспорт изображения из Photoshop и последующий импорт результата не требуется.

## Возможности

- генерация через **ComfyUI** и **Forge Neo**;
- работа с несколькими ComfyUI workflow и Forge-пресетами;
- inpainting через **Quick Mask**;
- несколько входных изображений и Reference images;
- поддержка **LoRA**;
- библиотеки Prompt и Negative prompt;
- автоматический и ручной resize;
- Face Restore и Upscaler через Forge Neo;
- сохранение настроек отдельно для каждого workflow/пресета;
- восстановление параметров из ранее созданного слоя;
- работа из **Photoshop Actions**, в том числе без показа интерфейса;
- работа с ComfyUI или Forge Neo на другом компьютере в локальной сети.

## Требования

- Windows;
- Adobe Photoshop 2020 или новее;
- RGB-документ Photoshop;
- Python 3.9 или новее;
- ComfyUI, Forge Neo либо оба бэкенда;
- установленные модели и дополнительные компоненты, необходимые выбранному workflow или Forge-пресету.

## Установка

Рекомендуемая структура:

```text
Photoshop\Presets\Scripts\
├── img2img helper.jsx
├── img2img-api.pyw
└── forge-schemas\
    ├── sd.json
    ├── xl.json
    ├── flux.json
    └── ...
```

`img2img-api.pyw` и каталог `forge-schemas` также можно хранить в подпапке `lib`.

1. Установите Python 3.9 или новее.
2. Подготовьте нужный бэкенд:
   - для **ComfyUI** включите возможность экспорта workflow в API-формате;
   - для **Forge Neo** запустите Forge с включённым API.
3. Скопируйте файлы `img2img helper` в `Photoshop\Presets\Scripts`.
4. Перезапустите Photoshop.
5. Запустите ComfyUI, Forge Neo или оба бэкенда.
6. В Photoshop выберите:

```text
File → Scripts → img2img helper
```

При первом запуске скрипт автоматически подготовит необходимые компоненты. Интернет для обычной локальной генерации не требуется; он нужен только для установки отсутствующих компонентов и функции перевода промпта.

## Быстрый старт

1. Откройте RGB-документ.
2. Выделите область, которую хотите обработать.
3. Запустите `img2img helper`.
4. При первом использовании откройте общие настройки кнопкой `⚙`.
5. Для ComfyUI укажите каталог с API-workflow. Для Forge Neo при необходимости укажите каталог `forge-schemas`.
6. Выберите **Backend** и нужный workflow или Forge-пресет.
7. Настройте Prompt, модель и остальные нужные параметры.
8. Нажмите **Generate**.

Если запущены оба бэкенда, между ними можно переключаться прямо в главном окне. Если доступен только один, скрипт использует его.

Результат появляется в Photoshop отдельным слоем:

```text
generated image
```

К нему добавляется маска исходного выделения.

Если генерация вернула несколько изображений, в Photoshop помещается первое.

## Работа с ComfyUI

### Подготовка workflow

`img2img helper` использует workflow, сохранённые в **API-формате**.

Перед использованием:

1. откройте workflow в ComfyUI;
2. подготовьте его так, как он должен работать;
3. экспортируйте через **Export Workflow (API)**;
4. сохраните JSON в каталог, выбранный в настройках `img2img helper`.

Если workflow был изменён, экспортируйте его заново и замените API-файл.

Скрипт запоминает настройки каждого workflow отдельно, поэтому после обычного перезапуска Photoshop повторно настраивать его не требуется.

### Настройка workflow

Кнопка `⚙` рядом со списком workflow открывает его пользовательские настройки.

Здесь можно выбрать:

- какое изображение получает данные из Photoshop;
- какая маска используется для inpainting;
- какие входы являются Reference;
- что делать с остальными `LoadImage`;
- какое изображение возвращается в Photoshop;
- как управляется размер;
- JPG или PNG для результата;
- какие параметры показывать в главном окне;
- кратность размера.

Если автоматический анализ сделал неоднозначный выбор, достаточно открыть это окно и назначить нужные элементы вручную.

### Несколько LoadImage

Если workflow содержит несколько `LoadImage`, каждому входу можно задать понятную роль.

**Photoshop image**  
Основное изображение из текущего выделения Photoshop.

**Reference**  
Референсное изображение. Для таких входов файл выбирается в интерфейсе `img2img helper`.

**Workflow file**  
Скрипт не заменяет изображение и оставляет файл, который записан в самом API-workflow.

**Empty image**  
Вместо файла используется пустое изображение.

Это особенно важно учитывать при сохранении API-workflow: если в `LoadImage` в момент экспорта уже был выбран файл, ссылка на него остаётся в JSON. При роли **Workflow file** этот файл будет использоваться при генерации.

Поэтому перед экспортом workflow можно:

- очистить `LoadImage`, если файл не должен участвовать в дальнейшей работе;
- либо специально оставить файл, если он должен постоянно использоваться в этом workflow.

После ручной настройки ролей скрипт запоминает ваш выбор и не пытается заново назначать удалённые вами Reference-входы.

### Выходное изображение и маска

Если workflow содержит несколько подходящих выходов или вариантов маски, выберите нужный вариант в настройках workflow.

Если выбранная нода позже была удалена или изменилась, скрипт сообщит об этом и предложит заново проверить настройки, вместо того чтобы молча использовать другой вариант.

### Управление размером

Для ComfyUI доступны три пользовательских режима:

- **Автоматически** — скрипт использует подходящие поля Width/Height, если их удалось определить однозначно;
- **Размер входного изображения** — размер определяется самим изображением и логикой workflow;
- **Выбранные поля Width/Height** — нужная пара указывается вручную.

Если workflow сам получает размер из входного изображения, обычно удобнее выбрать **Размер входного изображения**.

### Quick Mask inpainting

Для inpainting:

1. перейдите в Photoshop в режим **Quick Mask**;
2. создайте маску области, которую разрешено менять;
3. не выходя из Quick Mask, создайте внешнее выделение, определяющее границы отправляемой области;
4. запустите генерацию.

В результате:

- выделение определяет размер отправляемого фрагмента;
- Quick Mask определяет, какие пиксели внутри него можно изменять.

## Работа с Forge Neo

Forge Neo использует готовые JSON-пресеты из каталога `forge-schemas`.

В зависимости от установленного набора могут быть доступны пресеты для SD/SDXL, FLUX, KLEIN, QWEN, KREA 2, Lumina, Anima, Ernie, Z-Image, Face Restore, Upscaler и других поддерживаемых режимов.

После выбора пресета в главном окне показываются только относящиеся к нему параметры.

### LoRA

LoRA выбираются через отдельный диалог.

Выбранные LoRA и их веса запоминаются для соответствующего Forge-пресета. При сохранении Prompt-пресета в него записывается только текст промпта — список LoRA остаётся отдельной настройкой.

### ImageStitch

В поддерживаемых Forge-пресетах можно использовать до трёх дополнительных изображений.

Поддерживаются:

```text
jpg, jpeg, png, webp
```

Недоступные или повторяющиеся файлы автоматически исключаются. Если подходящих файлов не осталось, обычная генерация всё равно может быть выполнена без ImageStitch.

### Face Restore и Upscaler

**Face Restore** позволяет использовать доступные в Forge Neo методы восстановления лиц.

**Upscaler** позволяет выбрать коэффициент увеличения и доступный upscaler.

Набор параметров зависит от выбранного Forge-пресета и возможностей установленного Forge Neo.

## Промпты и пресеты

Для Prompt и Negative prompt используются отдельные библиотеки.

| Кнопка | Действие |
|---|---|
| `↻` | восстановить текст выбранного пресета |
| `+` | создать новый пресет из текущего текста |
| `✔` | обновить выбранный пресет |
| `×` | удалить выбранный пресет |

Пресет по умолчанию удалить или перезаписать нельзя.

Скрипт помнит последний выбранный Prompt/Negative Prompt preset **отдельно для каждого workflow или Forge-пресета**. Если после выбора пресета вы вручную изменили текст, выбранный пресет не теряется, а интерфейс показывает, что текст отличается от сохранённого варианта.

Кнопка перевода переводит текущий промпт на английский язык. Для этой функции требуется интернет.

В Forge Neo при обычном **CFG Scale ≤ 1** Negative prompt автоматически отключается.

## Размер и размещение результата

### Auto resize

При включённом **Auto resize** скрипт рассчитывает масштаб по размеру исходного выделения и выбранному resize-профилю.

Расчёт выполняется заново для каждой области.

Если вручную сдвинуть ползунок масштаба, **Auto resize отключается**, а выбранное значение становится постоянным ручным масштабом для текущего workflow или Forge-пресета.

Чтобы снова вернуться к автоматическому расчёту, включите **Auto resize**.

### Ручной режим

При выключенном **Auto resize** выбранный масштаб сохраняется и используется в следующих запусках этого workflow или Forge-пресета.

### Кратность размера

Для каждого workflow или Forge-пресета можно задать собственную кратность размера.

Перед генерацией область уменьшается до ближайшего подходящего размера, не выходя за границы исходного выделения.

### Размещение результата

Полученное изображение помещается обратно в исходную область Photoshop.

В общих настройках можно выбрать способ размещения и необходимость сохранения пропорций.

## Управление workflow и пресетами

Рядом со списком workflow/Forge-пресетов доступны основные действия:

| Кнопка | Действие |
|---|---|
| `↻` | обновить список или данные выбранного элемента |
| `⟳` | повторно проверить выбранный workflow/пресет или выполнить полный сброс его настроек |
| `✔` | сохранить настроенную копию через Save As |
| `⚙` | открыть настройки выбранного workflow/пресета |

**Обычное обновление** сохраняет ваши значения.

**Полный сброс** удаляет сохранённые пользовательские настройки только для выбранного workflow или Forge-пресета.

Если вы добавили новый JSON-файл в каталог, используйте кнопку обновления списка. При обычном открытии интерфейса скрипт использует уже сохранённый список и не требует повторного поиска всех файлов.

## Метаданные и Photoshop Actions

### Метаданные слоя

При включённом сохранении метаданных слой `generated image` хранит настройки, с которыми он был создан.

Если активный слой содержит такие данные, в верхней части окна появляется кнопка **LOAD**.

Она позволяет восстановить:

- использованный backend;
- workflow или Forge-пресет;
- Prompt и остальные значения;
- настройки resize;
- Reference images;
- LoRA и другие относящиеся к выбранному профилю параметры.

Это удобно для повторной генерации или продолжения работы позже.

### Photoshop Actions

Параметр **Record settings to action** определяет, как Action будет использовать настройки.

**Выключено**  
Action запускает скрипт с текущими пользовательскими настройками. Если позже вы сменили workflow, модель или другие значения, Action будет использовать новые значения.

**Включено**  
Action получает собственный снимок настроек и при воспроизведении использует именно его.

Для записанного Action скрипт не подменяет выбранный backend, workflow или Forge-пресет другим вариантом. Если нужный backend недоступен либо записанный workflow/schema был удалён, Action завершается с понятной ошибкой.

Это делает Action предсказуемым: он либо выполняется с теми настройками, для которых был записан, либо сообщает, что эти настройки больше недоступны.

Показ интерфейса при запуске из Action управляется стандартным переключателем диалога у шага Photoshop Action.

Если диалог выключен и настройки остаются валидными, генерация выполняется без открытия главного окна.

## Работа по локальной сети

ComfyUI или Forge Neo могут работать на другом компьютере.

В общих настройках укажите адрес этого компьютера и нужный порт. После этого `img2img helper` используется так же, как при локально запущенном backend.

## Устранение проблем

### Workflow отсутствует в списке

Проверьте:

- выбран ли правильный каталог;
- сохранён ли workflow через **Export Workflow (API)**;
- не был ли JSON перемещён или удалён.

После добавления нового файла обновите список workflow.

### Workflow работает не так, как ожидалось

Откройте настройки кнопкой `⚙` и проверьте:

- **Photoshop image**;
- Reference-входы;
- роли остальных `LoadImage`;
- маску inpaint;
- Output image;
- способ управления размером.

Если структура workflow была существенно изменена, выполните повторный анализ.

### Вместо ожидаемого изображения используется старый файл

Проверьте роли `LoadImage`.

Если для входа выбрано **Workflow file**, используется файл, сохранённый в самом API-workflow. При необходимости очистите соответствующую `LoadImage` в ComfyUI и заново экспортируйте workflow либо назначьте ей другую роль в настройках скрипта.

### Не работает inpainting

Убедитесь, что:

- Quick Mask действительно содержит маску;
- создано внешнее выделение;
- в настройках workflow выбран правильный вариант **Маска inpaint**;
- workflow действительно использует выбранную маску.

### Не запускается записанный Action

Если для Action была включена запись настроек, убедитесь, что по-прежнему доступны:

- записанный backend;
- записанный workflow или Forge schema;
- используемые модели и остальные выбранные значения.

Скрипт специально не переключает такой Action на другой backend или другой JSON.

### Backend не обнаружен

Проверьте, что ComfyUI или Forge Neo запущен и доступен по адресу, указанному в настройках.

Если вы только что запустили backend, используйте кнопку повторной проверки.

### Python не запускается

Проверьте, что Python установлен, а `img2img-api.pyw` находится рядом с JSX либо в подпапке `lib`.

Если скрипт показывает сообщение об ошибке запуска, ориентируйтесь прежде всего на текст этого сообщения.

## Ограничения

- поддерживается Windows;
- Photoshop-документ должен быть в режиме RGB;
- Automatic1111 и старые версии Forge официально не поддерживаются;
- нужные модели, LoRA и дополнительные компоненты должны быть установлены заранее;
- если backend возвращает несколько изображений, в Photoshop помещается первое.
